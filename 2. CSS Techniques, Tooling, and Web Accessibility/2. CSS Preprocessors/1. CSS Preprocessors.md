## CSS Preprocessor
A CSS preprocessor is a tool which enhances the capabilities of regular CSS, offering advanced features that simplify and improve your workflow. With preprocessors, developers can write code in a more structured and efficient way, using features like **variables**, **nesting**, and **mixins**, which are then compiled into standard CSS that browsers can interpret. While some of these features, such as variables and nesting, are now available in standard CSS, preprocessors still offer unique advantages. For example, preprocessor variables are more powerful as they allow calculations and can be used in older browsers. Preprocessor nesting syntax also enables deeper organizational flexibility that CSS alone does not yet fully replicate.


### Commonly Used Preprocessors
While there are several preprocessors available, the most widely used ones are:
- **Sass**: Known for its rich feature set and ease of use.
- **Less**: Similar to Sass but with a slightly different syntax.
- **Stylus**: Offers more flexibility in syntax but is less common.


### Purpose
- **Improved Readability**: Features like nesting and variables make your stylesheets easier to understand and maintain
- **Modularity**: Preprocessors allow you to split your CSS into multiple files, making it easier to organize and manage large projects
- **Consistency**: Variables and mixins ensure uniform styles across your project
- **Efficiency**: Reduces repetitive tasks and boilerplate code, giving you more time to focus on functionality and user experience


### Sass VS CSS
- Sass nesting is compiled to flat css, so its supoorted by all browsers (after compilation). But, for CSS nesting no compilation is done, so only the modern browsers can understand. Because of the same reason, media query nesting in css is only supported in modern browser.
- Sass Variables evaluated at compile time, exist only while building CSS, and browser never sees them. Sass Variables are lexical scope, do not inherit and block-based. Sass variable cannot change after build, cannot react to user actions.
- CSS Variables are DOM-based scope, inherit automatically, cascade like normal CSS. Css variables can change dynamically via JavaScript, media queries, pseudo-classes.
```
// sass
$color: red;
.card {
  $color: blue;
  color: $color; // blue
}
.button {
  color: $color; // red
}
```
```
// css
:root {
  --color: red;
}
.card {
  --color: blue;
}
.card p {
  color: var(--color); /* blue */
}
```


### Preprocessors And CSS Methodologies
Preprocessors work seamlessly with methodologies like BEM and SMACSS. With **BEM**, **Nesting** reduces the repetition often found in BEM class names Example :
```
.button {
    &__label {               
       font-size: 16px;
    }
    &--primary {               
       background-color: $primary-color;
       color: white;
    }
}
```
With **SMACSS**, Modular files align naturally with SMACSS categories (e.g., base, layout, modules) Example File Structure :
```
styles/
├── base/_reset.scss
├── layout/_header.scss
├── modules/_button.scss
├── state/_is-hidden.scss
├── theme/_dark-mode.scss
```



## Sass
**Sass**, short for **Syntactically Awesome Stylesheets**, is a CSS preprocessor which enhances the way developers write styles. As browsers can only interpret CSS, developers write their styles in Sass using a more advanced syntax, which is then compiled into standard CSS files. Sass provides two syntax options:

- **SCSS (Sassy CSS)**: A syntax that closely resembles traditional CSS, using `{}` and `;`. SCSS is the more popular syntax due to its familiarity and flexibility.
- **Sass**: An older syntax that relies on indentation and newlines instead of braces and semicolons. While still supported, it’s less commonly used today.

Sass files must be saved with the `.scss` or `.sass` extension, which then need to be compiled into standard `.css` files. This compilation process ensures your Sass code can be read by browsers. Modern tools, such as a Live Sass compiler in VS Code, automate this workflow, making the transition from Sass to CSS seamless.


### Key Features
### Nesting
Nesting allows you to write styles that reflect the structure of your HTML. This eliminates the need to repeat parent selectors, making your code more concise and easier to read.

#### Styles in CSS:
```
.nav {
  background-color: #f8f9fa;
}
.nav li {
  margin: 5px 0;
}
.nav li a {
  text-decoration: none;
  color: #007BFF;
}
```

#### Styles using SCSS:
```
.nav {
  background-color: #f8f9fa;

  li {
    margin: 5px 0;

    a {
      text-decoration: none;
      color: $primary-color;
    }
  }
}
```

#### Parent Selector
The `&` symbol, known as the **parent selector**, is a Sass feature which references the current parent selector. This is particularly useful for stateful or modified versions of a component.
```
.button {
  padding: 10px;
  background-color: $primary-color;
  &:hover {
    background-color: darken($primary-color, 10%);
  }
  &--large {
    padding: 20px;
  }
}
```


### Compiling Sass
Because browsers can only read CSS, your Sass files need to be compiled. This process transforms your `.scss` files into standard `.css` files. Once compiled, your SCSS code becomes browser-ready CSS, seamlessly integrating into your project. Popular tools for compilation include:
- **VS Code extensions**: Tools like **Live Sass Compiler** make it easy to compile SCSS files in real time
- **Command-line tools**: For developers who prefer terminal workflows, the **Sass CLI** provides an efficient way to compile files


### Variables
- **Maintainability**: By defining values in one place, you can update them globally with a single change.
- **Consistency**: Variables ensure uniform styling for common elements like brand colours or typography.
- **Efficiency**: Reduces repetitive typing and speeds up production time.
```
//_variables.scss
$primary-color: #4CAF50;
$secondary-color: #FFC107;
$font-primary: 'Roboto', sans-serif;
```
```
//styles.scss
.button {
    background-color: $primary-color;
    color: white;
    font-family: $font-primary;
}
```


### Partials
- **Organization**: Keeps styles modular and prevents large, unwieldy CSS files
- **Scalability**: Easier to manage styles for growing projects by focusing on small, reusable pieces
- **Reusability**: Components or patterns can be isolated for use across multiple projects

Partial files are named with a leading underscore (e.g., `_header.scss`), signaling to the compiler that they should not generate their own CSS file. Instead, partials are imported into a main Sass file using the **@use** keyword. Example Folder Structure :
```
scss/
   styles.scss
   partials/
        _variables.scss
        _header.scss
        _buttons.scss
```
```
// import into style.scss
@use 'partials/variables';
@use 'partials/header';
@use 'partials/buttons';
```


### Mixins
**mixins** are reusable blocks of CSS that can accept arguments (variables) to introduce dynamic behavior. By defining a mixin once, you can apply it across your stylesheets wherever needed, reducing redundancy and improving consistency. Mixins can:
- Accept multiple parameters to dynamically alter styles.
- Incorporate calculations and logic to handle complex requirements.
- Combine with other Sass features like variables and nesting for powerful results.

### Why Use Mixins
- **Reusability**: Write once, reuse multiple times across components
- **Consistency**: Maintain uniform styles for similar elements
- **Flexibility**: Customize styles dynamically using parameters
- **Scalability**: Simplify updates by centralizing reusable logic


#### Basic Styling
```
//_mixins.scss
@mixin fontStyle($size, $weight: bold, $color: #333) {
      font-size: $size;
      font-weight: $weight;
      color: $color;
}
```
```
//styles.scss
h1 {
       @include fontStyle(32px, bold, #007BFF);
}
```

#### Responsiveness
```
//_responsive.scss
@mixin responsivePadding($padding) {
     padding: $padding;
     @media (min-width: 768px) {
         padding: $padding * 1.5;
     }
}
```
```
// style.scss
.card {
    @include responsivePadding(10px);
}
```
```
// compiled css
.card {
    padding: 10px;
}
@media (min-width: 768px) {
    .card {
        padding: 15px;
    }
}
```

#### Using Logic
```
//_button.scss
@mixin buttonStyle($type) {
    @if $type == 'primary' {
        background-color: #007BFF;
        color: white;
    } @else if $type == 'secondary' {
        background-color: #6c757d;
        color: white;
    } @else {
        background-color: #f8f9fa;
        color: #333;
    }
        padding: 10px 20px;
        border: none;
        border-radius: 4px;
}
```
```
.button-primary {
    @include buttonStyle('primary');
}
```

#### Nested Selector
```
//_nav.scss

@mixin navStyle($bg-color) {
    background-color: $bg-color;
    padding: 1rem;
    ul {
        list-style: none;
        display: flex;
        li {
           margin-right: 1rem;
        }
    }
}
```
```
nav {
    @include navStyle(#333);
}
```



## NOTE
- Sass variables are replaced before your CSS is generated, they do NOT exist in the final CSS and they cannot be changed at runtime.Variables are valid only within the file or block where they are defined, no global access unless imported. This is best for consistent colors, spacing, fonts calculations, mixins and functions, build-time theming. This can not be change based on user interaction or based on dark/light theme toggles (without recompiling), also cant be accessed in JavaScript.
- Css custome variables remain in the browser and they can be changed dynamically without recompiling CSS. Its inherited through the cascade, a variable defined in a parent affects children. Css variables are great for themes, user interaction, realtime updates, dynamic styling. It can not perform calculations before rendering. There is runtime overhead invloved, compared to this sass variables are faster as they precompiled.
