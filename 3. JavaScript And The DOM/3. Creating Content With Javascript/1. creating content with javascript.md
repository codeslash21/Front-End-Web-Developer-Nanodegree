## textContent VS innerText
```
const element = document.querySelector('#dashboard')
const elementText = element.textContent
element.textContent = "Hi! I'm your new text."
```
```
// index.html
<div id="box">
  Hello
  <span style="display:none">Hidden</span>
</div>
```
```
const el = document.getElementById("box");
console.log(el.textContent);  // Hello Hidden
console.log(el.innerText);  // Hello
```
**textContent**
- returns all text inside the node
- includes hidden text
- includes text from all descendants
- ignores CSS

**innerText**
- returns only visible text
- respects CSS styles
- this excludes: `display: none` and `visibility: hidden`
- slower than `textContent`



## innerHTML
This property will return the HTML inside of your element, but not the element itself. It returns the HTML as a string so you can't really do much with it. But there is a potential problem. When you SET content with the `.innerHTML` property, it's not parsed as a string, but it's parsed as HTML. By using `.innerHTML`, we risk exposing our application to **XSS** attacks by opening up our application to new HTML. Imagine a black hat developer or scammer. They can come in to your application and find where you're inserting raw HTML, maybe it's in response to a form field. They can plug in some HTML to that form field and essentially hijack part of your site by deploying their own HTML into your page. You can mitigate that risk of these XSS attacks by sanitizing your inputs, but `.textContent` is already sanitized and therefore much safer to use.

**NOTE:**
- An XSS attack (Cross-Site Scripting) is a security vulnerability where an attacker injects malicious JavaScript into a trusted website, and that script runs in other users’ browsers.



## Modifying Element Attributes
- **`.classList`** this property simply gives you a list of all the classes associated with your element. This list is actually a read-only **DOMTokenList**. To manipulate this list we have access to powerful methods through the DOMTokenList API. Here we are dicussing some of the methods
  - **add()** adds a new class to the list of classes on the element. `element.classList.add('favorite')`
  - **remove()** removes a class from the list of classes on an element. `element.classList.remove('favorite')`
  - **toggle()** adds the class if not present or removes the class if the class is present. `element.classList.toggle('favorite')`
  - **contains()** returns a boolean true or false based on whether the .classList contains the class you pass into the argument.

- **`.className`** returns all the classes for your element. But it returns them as a string. If you have more than one class on an element, you'll get all the classes in a string. It's not comma separated or anything like that, it's just a string with spaces between each class. This string isn't read-only, you can modify it just by using a regular assignment with dot notation, this assignment overwrites all of the existing classes with your new value.

- Using the **`.style`** property, you're adding an inline style attribute to your element. If you want to change the text color it would be `element.style.color`, or if you want to change the background color it would be `element.style.backgroundColor`. If the CSS rule is more than one word, you need to combine it into one word using camelCase. You can set multiple values, but you just have to set them one at a time.

- **`.cssText`** If you need to add multiple style changes at once, then you can use the `.cssText` property. This let's you add a string containing all the properties you want to add. `element.style.cssText = 'color:white; background-color:red;'` When you directly assign values with .cssText, you will completely overwrite your existing inline style as well.

- **`.removeProperty()`** Just like you can add inline styles, you can remove inline styles on an element if you use the `.removeProperty` method and pass in the style you want to remove. `element.style.removePropery('color')` You could also pass an empty string to a style rule like this `element.style.color = ''`, both of these will result in the same look.

- **`.id`** we can use dot notation to modify the `id` of an element, `element.id = 'userData'`. Directly changing the value using dot notation completely replaces the current value.

- **`.setAttribute()`** we can assign attributes to DOM elements using this method. You pass two strings as arguments - the name of the property and the value of the property, `element.setAttribute('id', 'userData')`. This method is usefull if you're assigning custom data properties to your elements. Custom data properties are basically a way you can store data in your element that you can access via the DOM. But since they're custom properties, they don't exist in the element interface. So you can't directly assign them like you can other elements. When you use custom data attributes, you need to start the name with `data-`.



## DOM And CSSOM
At the same time the DOM is being constructed, your browser is working on building the **CSSOM**. That stands for the CSS Object Model. It's created practically the same way as the DOM is. It's just building the CSS to be used in the page. Once the CSSOM is built, the CSSOM and the DOM are combined into a render tree. This render tree contains every visible node and its content and styling. Now in the layout, or reflow, stage, the browser uses the render tree and calculates the size and position of every element on the screen. Once the layout stage is finished, the repaint stage begins. This is the point where the content is actually drawn on the screen in their calculated position with the associated styles from the render tree.

Any time we make a change to the DOM with our JavaScript, we change the render tree. Whether it's changing the style of an object or adding and removing objects, those changes will be reflected in either the DOM or the CSSOM. When either one of those changes, the render tree has to change since it's a combination of both. Depending on the changes you're making, that new render tree can trigger 
- a redo of the layout phase, also called a reflow
- a repaint of the elements, which is changing how they look
- both layout and repaint.

Since layouts of the document are very intensive operations, we want to minimize them as much as possible. Repaints aren't quite as intense but we still need to be aware of them since some things that we think of as repaints may actually cause reflows.

- **Layout changes:** For layout changes, any change that affects the size or position of elements on a page will trigger a layout change. So if you change the width of an element or change the border width or display property, layout change.
- **Repaints:** Any change to the way an element looks that doesn't affect its size or position will trigger a repaint. So changing the text color will just trigger a repaint but not a layout change. Be careful, though, some things that feel like they might only cause a repaint could trigger a layout change. For example, a change in the font-style of an element could cause a layout change. If switching to bold changes the space the font takes up, and then changes the wrapping of the text forcing the container of the text to be bigger… now you have a page-wide layout change.



## Document Fragment
A document fragment is essentially a small document object that doesn't affect the DOM. It works just like a regular object with nodes and elements as children and its own tree structure, but since it's not a part of the DOM, changes to it don't directly affect the DOM or the render tree, meaning they don't cause reflows or repaints.
```
const fragment = document.createDocumentFragment()
```
Now we have a fragment, we can simply add any elements we want to it and create our own node tree inside of it. We're basically creating a small family tree of elements inside our fragment. Once we're done, we add the entire fragment to the DOM. We're adopting the document fragment into the original document family tree. This works great because the document fragment itself isn't added to the DOM. Only the children we added inside the fragment are added. And since we're adding everything at one time, we're only making one change to the render tree and only triggering one layout and repaint. 



## Modify Element
### Create Element
```
const newElement = document.createElement('p')  // create a new p element
newElement.classList.add('regular')  // add a class
newElement.id = 'introParagraph'  // set an id
newElement.textContent = "I made this paragraph in JavaScript!"  // set text content
```


### Insert Element
- **`.append()`** adds your elements AFTER the last child of the reference element. The reference element is the parent and you're just adding more children to the parent at the end of the list of children. If you want to add several elements, you can pass more than one element in the argument, separated by commas, and it will add them as children in that order.
- **`.prepend()`** adds your elements before the first child of the reference element.
- **`.after()`** adds your element directly after your reference element as a sibling and not a child.
- **`.before()`** places a sibling element directly before your reference element instead of after it.
- **`.replaceWith()`** completely replaces an element with another element.
- **`.appendChild()`** the main difference between it and `.append()` is that `.appendChild()` can only take one argument.
- **`.insertBefore()`** is another method that works like the newer `.before()` method but the syntax is more complex. You need the parent element, then you pass in the element you want to insert and the reference element you want to insert before, `parentElement.insertBefore(elementToInsert, siblingElement)`.
- **`.insertAdjacentElement()`** takes two arguments: the location you want to insert and the element you want to insert. For the location you can pass in four strings. They are - `beforeBegin`, `afterBegin`, `beforeEnd`, `afterEnd`. `parentElement.insertAdjacentElement('location', element)`. You can actually get the exact same function with other more modern methods. `beforeBegin` **->** `begin`, `afterBegin` **->** `prepend`, `beforeEnd` **->** `append`, `afterEnd` **->** `after`.
- **`.insertAdjacentHTML()`** method that works the same as `insertAdjacentElement()`, but this method has the same risks as `innerHTML`.
- **`.remove()`** removes the element from the DOM completely, but removing an element doesn't remove all the references to that element. This method will also be usefull if you want to manually remove any event listeners in case you don't want to rely on the JavaScript garbage cleanup to handle it for you.
