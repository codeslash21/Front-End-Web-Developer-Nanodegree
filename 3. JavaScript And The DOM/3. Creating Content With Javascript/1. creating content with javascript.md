### textContent VS innerText
```
// index.html
<div id="box">
  Hello
  <span style="display:none">Hidden</span>
</div>
```
```
const el = document.getElementById("box");
console.log(el.textContent);  // Hello Hidden
console.log(el.innerText);  // Hello
```
**textContent**
- returns all text inside the node
- includes hidden text
- includes text from all descendants
- ignores CSS

**innerText**
- returns only visible text
- respects CSS styles
- this excludes: `display: none` and `visibility: hidden`
- slower than `textContent`


### innerHTML
This property will return the HTML inside of your element, but not the element itself. It returns the HTML as a string so you can't really do much with it. But there is a potential problem. When you SET content with the `.innerHTML` property, it's not parsed as a string, but it's parsed as HTML. By using `.innerHTML`, we risk exposing our application to **XSS** attacks by opening up our application to new HTML. Imagine a black hat developer or scammer. They can come in to your application and find where you're inserting raw HTML, maybe it's in response to a form field. They can plug in some HTML to that form field and essentially hijack part of your site by deploying their own HTML into your page. You can mitigate that risk of these XSS attacks by sanitizing your inputs, but `.textContent` is already sanitized and therefore much safer to use.

**NOTE:**
- An XSS attack (Cross-Site Scripting) is a security vulnerability where an attacker injects malicious JavaScript into a trusted website, and that script runs in other users’ browsers.
