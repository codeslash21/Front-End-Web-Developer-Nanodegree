## Event And Event Processor
When an event happens in the browser, like a click on an element,  it starts a process to handle that event and it's called **event processor**. To start with, the processor creates an event object to hold all the information for the event, including the type of event that happened. Then, starting at the `root` of the DOM, the processor goes down the DOM tree one element at a time. Navigating down the DOM tree is called the **capturing phase**. The process keeps going down in the capturing phase until it hits the element that's the target of the event. This is where the event originated. So if you click on a button, that button would be the target of the event. If you click on an anchor, that anchor would be the target of the event. Once the processor reaches the target of the event, it starts the **target phase** and adds all of the target information to the event object. This target information ends up being a property of the event that we can access. The property that holds that information is called `.target`. Now the processor goes back up the DOM tree to the root. This phase where the processor moves back up the tree is called the the **bubbling phase**. Once the processor reaches the root,  it's finished its job and it waits for the next event to fire.



## Event Listener
An event listener is a method you can attach to elements in your website. When you have an element and you add a listener to it, you tell the listener what type of event to listen for and then what to do when an event like that happens on that element. If you want to add an event listener, you use the method called `.addEventListener()`. This takes two arguments
- The type of event to listen for
- The callback function to call when the event occurs

```
const colorChanger = document.querySelector('.colorButton')
colorChanger.addEventListener('pointerdown', handleChangeColor)
```
