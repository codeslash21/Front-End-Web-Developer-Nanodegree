## Event Processor
When an event happens in the browser, like a click on an element,  it starts a process to handle that event and it's called **event processor**. To start with, the processor creates an event object to hold all the information for the event, including the type of event that happened. Then, starting at the `root` of the DOM, the processor goes down the DOM tree one element at a time. Navigating down the DOM tree is called the **capturing phase**. The process keeps going down in the capturing phase until it hits the element that's the target of the event. This is where the event originated. So if you click on a button, that button would be the target of the event. If you click on an anchor, that anchor would be the target of the event. Once the processor reaches the target of the event, it starts the **target phase** and adds all of the target information to the event object. This target information ends up being a property of the event that we can access. The property that holds that information is called `.target`. Now the processor goes back up the DOM tree to the root. This phase where the processor moves back up the tree is called the the **bubbling phase**. The callback function execution happens as part of the bubbling phase. Once the processor reaches the root,  it's finished its job and it waits for the next event to fire.



## Event Listener
An event listener is a method you can attach to elements in your website. When you have an element and you add a listener to it, you tell the listener what type of event to listen for and then what to do when an event like that happens on that element. If you want to add an event listener, you use the method called `.addEventListener()`. This takes two arguments
- The type of event to listen for
- The callback function to call when the event occurs

```
const colorChanger = document.querySelector('.colorButton')
colorChanger.addEventListener('pointerdown', handleChangeColor)
colorChanger.removeEventListener('pointerdown', handleChangeColor)
```

- We should use pointer events over mouse events, because mouse click events are specific to using a mouse, while pointer events can handle mouse, touch, stylus, and other input types. In fact, pointer events are an extension of mouse events.
- It's recommended to name your callback functions in event handlers with a `handle` prefix. It's recommend using named functions for your callbacks, you can define anonymous functions for your event handler but that can cause problems when we will remove the listener. In the following case the events are identical so that's fine. But the callbacks aren't the same, because during the application's creation phase, each anonymous function is given its own space in memory. Since the memory location for the remover is not the same as the memory for the listener, they're not referentially equal. Even though the functions look identical, to JavaScript they're different functions. So in this case, the listener won't be removed like you can expect. In some cases, these listeners may get cleaned up on their own by the browser. But in a large site or single page application, handling memory leaks can be important.
```
const colorChanger = document.querySelector('.colorButton')
colorChanger.addEventListener('pointerdown',  () => {console.log('clicked') }
colorChanger.removeEventListener('pointerdown',  () => {console.log('clicked') }
```



## Event Object
The first thing the browser does when it detects an event is it creates an `event` object. Once the event object is made, the event processor travels down the DOM until it finds the target of the event, then it adds that element information to the event object. The event listener automatically pass the event object as an argument to your callback function. You can treat `event.target` as an element found with `.querySelector()` or any other method for selecting elements. `event.target.classList.toggle(“active”)`. If we dont want to execute the default action of that `event`, then we call `.preventDefault()` method on the `event` object.

In bubbling phase event processor move up through the DOM tree. Because of this we can add the listener to the parent instead of adding to all the children, and listner will execute the callback function on the parent to handle the event with target data from the child. So with only one listener we can get the target data from every child of that parent. Instead of hundreds of listeners we're down to one listener. That can be a huge savings in terms of memory usage and management of your listeners. 



## NOTE:
- When we import our JavaScript in HTML file using `script` tag we will add `defer` attribute there, this will tell the browser to wait until the DOM is finished before loading the script. This makes sure your script only runs after the DOM has been completely parsed and all of your DOM elements are in place. If we dont add `defer` attribute then browser will start loading the javascript once it sees the `script` tag and if our script has some reference to a DOM element like you would with any listeners or `.querySelector()`, we will get an error.
