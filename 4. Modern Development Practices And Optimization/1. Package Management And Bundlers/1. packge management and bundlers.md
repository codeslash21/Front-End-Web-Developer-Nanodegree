## Package Management

We use package managers like **NPM** (Node Package Manager) and **Yarn** (Yet Another Resource Negotiator) to simplify the process. These tools automate dependency installation, handle version management, and resolve sub-dependencies (dependencies of dependencies) seamlessly. Both of these popular, JavaScript-based, open-source tools rely on a file called `package.json`. This file serves as a blueprint for configuring a development environment.
```
npm init   // for initializing package.json file with configuring metadata
npm init -y   // for initializing package.json file, skipping the configuration questions
```
- `package-lock.json` file is automatically generated and updated after every npm install. It contains the exact versions of the dependency tree (the relationship between dependencies and sub-dependencies) and every installed dependency. It allows faster installations by skipping already installed dependencies or sub-dependencies. It ensures greater consistency between development environments and builds. It’s good practice to include the package-lock.json file alongside your package.json in repositories and during deployment.



## NPM
| Command	What | It Does |
| -------------|---------|
| npm init | Initializes a package.json file through a guided configuration |
| npm install or npm i | Installs all the dependencies listed in the package.json |
| npm install <package> |	Installs a dependency and adds it to dependencies in package.json and package-lock.json |
| npm install <package> --save-dev | Installs a dependency and adds it to `devDependencies` in package.json |
| npm install -g <package> | Installs a dependency globally for use anywhere on your system |
| npm uninstall <package>	| Uninstalls a dependency and removes it from the package.json |
| npm update |	Updates all the installed dependencies to their latest compatible versions |
| npm run <script> | Runs a specified script from the scripts section in the package.json |


### Best Practices NPM
- Don’t manually edit `node_modules`, let npm manage this directory entirely.
- Add node_modules to `.gitignore` Prevent it from being pushed to remote repositories.
- Use and commit `package-lock.json` Ensure consistent dependencies across environments.
- Remove unused dependencies Keep your project lightweight and clean.
- Regularly update dependencies use `npm outdated` and `npm update` to stay current.
- Run `npm audit` and `npm audit fix` to identify and resolve vulnerabilities in your dependencies.
- Update your project metadata, include essential details like the project name, version, description, and license in `package.json`.



## Yarn
Yarn was created by Facebook to address some of npm's shortcomings. It offers all the functionality of npm and more, including:

- **Faster Installations** Yarn speeds up dependency installation with parallel processing.
- **Offline Caching** Improves performance by allowing cached dependencies to be installed offline.
- **Dependency Locking** Uses `yarn.lock`, similar to npm’s `package-lock.json`, for consistent dependency versions.
- **Enhanced Security** Verifies package integrity using checksums.
- **Plug’n’Play (PnP)** Replaces the `node_modules` folder with a more optimized dependency architecture.


| Command	What | It Does |
| -------------|---------|
| yarn init | Initializes a package.json file through a guided configuration |
| yarn add <package> | 	Installs a dependency and updates the dependencies section in package.json |
| yarn add <package> --dev |	Installs a dependency and updates the `devDependencies` section in package.json |
| yarn remove <package> | Removes a dependency and updates the package.json file |
| yarn install | Installs all dependencies listed in the package.json file |
| yarn upgrade	| Updates package dependencies to their latest compatible versions |
| yarn audit | Checks for vulnerabilities in the project’s dependencies |



## Bundlers
When preparing your application to meet your users' needs, it's crucial to leverage modern tools that organize, manage, and optimize your code. Bundlers are tools for that job. They streamline the process of preparing your application for production, optimizing it for browsers and enhancing its performance, resulting in faster and more efficient user experiences.


### Minification and Concatenation
Good coding practices include keeping your code modular, separating it into files, making it easy to read, and including plenty of comments. These habits make your code more maintainable and easier to debug for humans. However, browsers don’t debug code—they have no use for comments, white space, or multiple files. In fact, these can slow down your application. Thankfully, you don’t have to choose between clean, readable code and optimized browser performance. This is where bundlers shine

#### Minification
Bundlers perform tasks like minification (sometimes called "uglification"), which removes unnecessary elements such as white space, comments, and anything else that isn’t required for the browser to execute your code. While minification may make your code appear "ugly" by compressing it into one line (making it harder for humans to parse), it dramatically improves load times and performance.

#### Concatenation
Bundlers may also handle concatenation, combining multiple files into a single, larger file. This helps us by reducing the number of HTTP requests browsers need to make, whichin turn increases your loading speed.


### Optimized Production Code
The minified and concatenated code is typically saved in a designated folder, often called `dist` or `build`. This production-ready code is separate from the clean, modular source code you work on during development. This separation ensures your source code remains easy to read and maintain while the production code is fully optimized for the browser. With bundlers, you get the best of both worlds: clean development practices and high-performance applications for your users.



## Webpack
To bundle an application effectively, Webpack needs some instructions. Think of it like a blueprint. You'll need to specify the entry point for your application, where the bundled static files should be output, and any additional loaders or plugins you want to include for extra functionality. `webpack.config.js` is the Webpack configuration file and it is an object exported using `module.exports`. This object contains key-value pairs that guide Webpack on what actions to perform in specific scenarios. 

### Entry point
The entry point is the starting file Webpack uses to navigate through your application and build its dependency graph. You can define one or multiple entry points. By default, the entry point is usually set to `./src/index.js`.


### Output
The output will include the folder and file generated by Webpack. The path to the output file must be an absolute path. To achieve this without manually writing the path, we use Node.js's built-in `path` module. To configure the output, use the `output` key, which contains an object. This object should include:
- A `path` key specifying the absolute path to the output folder (commonly named `dist`).
- A `filename` key specifying the name of the file generated by Webpack that will contain your optimized code.

```
const path = require('path');

module.exports = {
  mode: "production",
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'), 
    filename: 'main.js', 
  },
};
```


### Loaders
Loaders extend webpack's ability to process various file types. By default, webpack handles JavaScript and JSON. However, to process other file types, such as CSS, you'll need to configure a specific loader. To do this, we'll add a new key, `module`, to our `webpack.config.js` file. This key defines the rules for how webpack interacts with different file types. The module object contains a `rules` property, which is an array of objects representing the loaders. Each loader object includes two key properties:
- **test**: Specifies the file types to match (e.g., .css files).
- **use**: Defines the loader(s) to apply to those files.

This setup ensures that webpack knows how to handle and process the specified file types. To use a loader, you'll need to install it. For this example we will take a look at two loaders, `css-loader` processes CSS files, while `style-loader` injects the processed CSS into the DOM. `npm install --save-dev css-loader style-loader`. You need to import your CSS within the file structure connected to your entry point. Start by importing the CSS directly into your entry point file. `import "../styles/style.css"`
```
module.exports = {
  // Earlier configuration here
  module: {
    rules: [
      {
        test: /\.css$/i, // Matches .css files
        use: ["style-loader", "css-loader"], // Loaders to process and inject CSS
      },
      {
        test: /\.png$/i, // Matches images with .png exntension
        type: "asset",
      },
    ],
  },
};
```


### Plugins
With our current setup, CSS is bundled within main.js. However, for better performance, we might want to extract the CSS into its own file and minimize it. **MiniCssExtractPlugin** and **CssMinimizerWebpackPlugin** plugins help achieve that. To use them, start by installing the plugins: `npm install css-minimizer-webpack-plugin mini-css-extract-plugin --save-dev`
```
const MiniCssExtractPlugin = require("mini-css-extract-plugin");
const CssMinimizerPlugin = require("css-minimizer-webpack-plugin");
const TerserPlugin = require("terser-webpack-plugin")


module.exports = {
          // Earlier configuration here
          plugins: [
            new MiniCssExtractPlugin({ filename: "main.css" }),
          ],
          optimization: {
            minimizer: [
              new CssMinimizerPlugin(),
              new TerserPlugin()

            ],
          },
          module: {
            rules: [
              {
                test: /\.css$/,
                use: [
                  MiniCssExtractPlugin.loader,
                  "css-loader",
                ],
              },
            ],
          },
};
```
- Unlike loaders, plugins need to be explicitly imported. In this example, we've imported `MiniCssExtractPlugin` and `CssMinimizerPlugin` into our `webpack.config.js`.
- We then add the `plugins` key to our configuration and set it to an array. This is where we define the plugins that webpack will use.
- To use `MiniCssExtractPlugin`, we instantiate it with the `new` keyword and pass it an object with a `filename` key set to `main.css`. This specifies the name of the file where the extracted and minimized CSS will be saved.
- Next, we add the `optimization` key to the configuration. Webpack uses this section to determine which optimizations to apply based on the mode (e.g., development or production). Here, we define a `minimizer` key with an array value. Within this array, we initialize and add `CssMinimizerPlugin` to handle CSS minimization.
- To make sure webpack is using our plugin with our css files we are going to need to replace the style-loader with a loader provided by our `MiniCssExtractPlugin`.
- Once we start specifying plugins, some of webpack's default behavior is overridden. For example, webpack automatically minifies JavaScript files by default. However, when we add custom plugins, this behavior is removed. To restore JavaScript minification, we need to explicitly include the `TerserPlugin` in the plugins array. This plugin is included with webpack by default, so we only need to require it in the `webpack.config.js` file to use it.
