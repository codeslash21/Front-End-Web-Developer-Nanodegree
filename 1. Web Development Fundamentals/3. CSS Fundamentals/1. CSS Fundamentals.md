## HTML Class and ID
- The **class** attribute is used to group multiple elements together, enabling the same styles or functionality to apply to all of them. You can assign multiple classes to an element by separating them with spaces, making class highly versatile and reusable.
- The **id** attribute is meant to uniquely identify a single element. It should only appear once per page, as repeating the same id can cause errors or unpredictable results. IDs are ideal for targeting one specific element when unique behavior or styling is required.


### Naming Conventions
There’s no fixed rule for naming class and id values, but consistency is important.
- **Kebab-case**: `button-primary` Common in CSS libraries like Bootstrap and aligns with CSS properties and values.
- **CamelCase**: `buttonPrimary` Often used in JavaScript. Use whichever naming convention fits your workflow, but ensure it's consistent throughout your project.



## Implementing CSS
### Inline Styles
- Declared directly within the style attribute of an HTML tag.
- Styles are written as a single line of CSS, with properties separated by semicolons.
- Inline styles are not reusable, make your HTML cluttered, and violate the DRY principle ("Don't Repeat Yourself"), which encourages reusing code to avoid duplication.
```
<h1 style="color: red; font-size: 24px;">Hello, world!</h1>
```


### Internal CSS
- Written in a `<style>` element within the `<head>` of the HTML document.
- Keeps HTML and CSS somewhat separate by moving styles out of individual tags.
- Useful for small, single-page projects but not scalable for larger websites.
```
<head>
    <style>
        h1 {
            color: red;
            font-size: 24px;
        }
    </style>
</head>
```


### External CSS
- This is not only the preferred method but also considered the general standard for professional web development.
- Styles are written in a separate `.css` file and imported into the HTML document using a `<link>` element.
- Keeps HTML and CSS completely separate, improving readability and maintainability.
- Allows a single stylesheet to be reused across multiple pages for consistency.
- Scalable for large projects and compatible with external libraries like Bootstrap.
- With external CSS, you can link multiple stylesheets to one page, combining custom designs with external resources. The **rel** attribute indicates the file type (stylesheet for CSS), and the href attribute specifies the file's location. For professional, maintainable, and scalable projects, external CSS is essential.
```
<head>
   <link rel="stylesheet" href="styles.css">
</head>
```



## Importing CSS Files
```
<head>
  <link rel="stylesheet" href="/css/header.css">
  <link rel="stylesheet" href="/css/footer.css">
</head>
```
To use multiple stylesheets, include them in your HTML like this. This modularity helps locate specific styles quickly while maintaining a clean structure. Remember, CSS cascading rules apply: styles from the last imported file will override any conflicting ones from earlier imports. CSS also supports importing stylesheets within other CSS files using `@import`. While this can consolidate your imports into a single file, it slows down page load times and is generally not preferred. Stick to `<link>` elements in your HTML for better performance. 
```
@import url('header.css');
@import url('footer.css');
```



## Priority and Specificity
As we build our pages and styles, we’ll encounter scenarios where multiple selectors apply to a single HTML element, and some of those selectors may have conflicting properties. CSS resolves these conflicts using a hierarchy of priority.


### Cascading Rule
```
.theme-dark {
  background-color: black;
  color: white;
}
.bg-green {
  background-color: green;
}
```
The most fundamental priority rule in CSS is the declaration order within the stylesheet itself, also known as the cascading rule. If both `.theme-dark` and `.bg-green` classes are applied to the same element, `.bg-green` takes priority for the background color because it is declared after `.theme-dark`. However, `.bg-green` only overrides the specific property it declares (background color); the text color from `.theme-dark` still applies.


### Specificity

CSS calculates specificity to determine which rule takes precedence when multiple selectors target the same element. To better understand how CSS calculates specificity, here’s a breakdown of how different selectors are scored:

<img width="694" height="316" alt="Screenshot 2026-01-14 at 17 52 30" src="https://github.com/user-attachments/assets/c4dc866c-2699-4afb-991c-9c77d8f972e2" />

```
div.sold-out {
  color: gray;   /* Specificity: 1 (element) + 10 (class) = 11 */
}
.product {
  color: blue;   /* Specificity: 10 (class) */
}
```
If we combine selectors, their points are added together. Here, `div.sold-out` has a specificity score of **11**, which is higher than `.product`'s score of **10**. Therefore, the `color: gray;` rule will apply.


### Important
`!important` overrides everything, even inline styles. The only thing that can override an `!important` rule is another `!important` rule declared later. While powerful, overusing `!important` is considered bad practice, as it can make your CSS harder to debug and maintain. Rely on proper selector specificity instead.

## Pseudoclass
A **pseudo-class** is a keyword added to a selector that specifies a special state or condition of an element. Instead of targeting an element based on its attributes or classes, a pseudo-class allows you to apply styles when the element is in a specific state, such as when it's being hovered over by the user, has focus, or is the first child of its parent. Pseudo-classes help enhance user interaction and provide dynamic styling without the need for JavaScript. A **pseudo-class** is written by appending a pseudo-class keyword to a regular selector, using a colon (`:`). This tells the browser to apply styles to an element when it is in a particular state, rather than selecting it based on its regular attributes. These pseudo-classes can be used with any regular selector to refine the state at which styles are applied.
```
button {
  background-color: green;
}
button:hover {
  background-color: yellow;
}
```
Other common pseudo-classes include:
- `:active` — applied when an element is being activated, like when a button is clicked.
- `:focus` — applied when an element (like an input field) gains focus, for example, when a user clicks into a text field or navigates to it with the keyboard.
- `target` when a particular element is targeted through `a` element. For example, there is a `div` with `id="popup"` and there is one `a` which refers to `#popup`, so when we click on the `a` element `#popup` will be added to the url, and that `div` is targeted.
- `hover` when cursor is on any html element.
- `link` generally defines default state for links. `button` element does not have `link` state.
- `visited` it defines the state for a link which is clicked. `button` element does not have `visited` state.
- `checked` it generally defines state for `input` of type `radio` or checkbox which is selected.
- `invalid` is generally related to input element and when user enter a value which is not aligned with the expected input format.
- `placeholder-shown` is generally related to input element, and when user did not enter any value in the input field.
- `:first-child` — targets an element that is the first child of its parent.
- `:nth-child([number])` — allows targeting specific child elements based on their position.


### Note
- On `focus` there is outline for `button` element by default. To remove that, we can use `outline: none;` style. But for accessibility reason we should not remove the `focus` state, rather we can modify the default design. For example, we can use the `hover` state for `focus` state as well.
- `button` element does not have `link` and `visited` state.



## Shorthand Properties
In CSS, shorthand properties allow you to combine related declarations into a single line of code. For example, instead of declaring separate properties for background-color, background-image, background-position, background-size, and background-repeat, you can use the background shorthand property.
```
// LONG FORM
background-color: #cce5ff;
background-image: url('logo.png');
background-position: 70px 30px;
background-size: 100px;
background-repeat: no-repeat;

// SHORT FORM
background: #cce5ff url('logo.png') 70px 30px / 100px no-repeat;
```
In the shorthand version, the values are combined into a single line. In this instance, the background-position and background-size values must be placed next to each other, separated by a forward slash (`/`), to indicate their measurements.



## Customizing Font
The most important property for font styling is font-family. This property defines the typeface for your text. You can specify multiple fonts in a list, and the browser will use the first available font in the list. This is helpful in case your preferred font is not available on the user's system. If none of the fonts are available, the browser will use a default system font. It's important to include fallback fonts to ensure that your text remains legible and styled appropriately, even if the primary font doesn't load. In the following case, the browser will try to use "Roboto" first. If it's not available, it will fall back to "Arial". If neither is available, it will default to a generic sans-serif font.
```
p {
    font-family: "Roboto", "Arial", sans-serif;
}
```


### Importing Font
To import fonts that aren’t available by default on the user’s device, we use the `@font-face` rule in CSS. This allows us to link to custom fonts either from a local source or an external URL. The `@font-face` rule requires a few properties:
- **font-family**: This is the name you’ll use to refer to the font in other parts of your stylesheet.
- **src**: Specifies the source of the font file. You can provide a local source or link to an external URL. You can provide as many URLs in the src property as you'd like. The browser will try each source in order until it successfully loads the font.
```
@font-face {
  font-family: 'MyCustomFont';
  src: local('Gloria'), 
       url('https://example.com/fonts/mycustomfont.ttf') format('truetype'),
       url('/myFonts/mycustomfont.ttf') format('truetype');
  font-weight: 700;  // bold, default: normal(400),
}
```
In this example, font-family is set to **MyCustomFont**. The src includes a local font check for `Gloria`, followed by a fallback URL to a font on an external site, followed by a fallback URL to a font file located in the `fonts` directory of the current website/project. If the local font isn't found, the browser will try fetching the font from the specified URLs.



## Common Font Formats
- **TrueType (TTF):** A widely used format that supports both Windows and Mac systems. It allows for scalable fonts, meaning that they can be resized without losing quality. 
- **OpenType (OTF):** An extension of TrueType that supports additional features like ligatures and advanced typographic options.
- **Web Open Font Format (WOFF):** A compressed format specifically designed for use on the web, which helps reduce file size and loading times.
- **Embedded OpenType (EOT):** A format primarily used for embedding fonts in web pages, mainly in Internet Explorer.

The Box Model in CSS defines the layout of HTML elements by outlining how their content is structured and spaced. Each element is treated as a rectangular box, with four key properties—margin, border, padding, and content—affecting its size and positioning within the page. Box Model properties are -
- **Margin**: Space outside the element, invisible, doesn't share background.
- **Border**: Surrounds the padding and content, has width and style.
- **Padding**: Space between the content and the border, visible and can have background color.
- **Content**: The actual content of the element.

By default `Final Height = bottom border + bottom padding + height + top padding + top border`. If we set `box-sizing: border-box;`, then `Final Height = height`, means border and padding will be included in our specified height for a particular element. `box-sizing` property dont get inherited by default, so we can use `inherit` value to force the element to use `box-sizing` value from its parent.
```
*,
*::before,
*::after {
  margin: 0;
  padding: 0;
  box-sizing: inherit;
}
body {
  box-sizing: border-box;
}
```


### Margin
```
margin: 10px 20px 30px 40px;
```
- Using `margin: auto` centers an element within its container if it has a specified width and the parent is larger.
- When two adjacent elements have vertical margins, they may collapse into a single margin, taking the larger of the two values. This is called **margin collapsed**.


### Border
```
border: 2px solid #000;
border-top: 2px solid #f00;

border-style: solid dotted dashed groove;
border-width: 2px 5px 3px 8px;
```


### Padding
```
padding-top: 10px;
padding-right: 30px;
padding-bottom: 20px;
padding-left: 25px;

padding: 10px 30px 20px 25px;
```


### Content Area
```
width: 200px;
height: 70px;
min-width: 50px;
max-height: 200px;
```



## Units Of Measurement
### px
- The most basic unit, representing the smallest visible unit on the screen.
- It's a fixed measurement, meaning it remains constant regardless of the screen size.


### rem
- Relative to the font size of the root element (16px default in most browsers).
- Ideal for scaling elements relative to the root font size, ensuring consistency across different screen sizes.
```
:root {
  font-size: 18px;  /* 1rem = 18px */
}
.example {
  font-size: 2rem;  /* 2 * 18px = 36px */
}
```


### em
- Relative to the font size of the current element.
- Will inherit font size from ancestor elements.
```
button {
  font-size: 24px;
  padding: 1em 3em;
}
```


### vw and vh
- Relative to the size of the viewport (**browser window**).
- 1vw = 1% of the viewport width, 1vh = 1% of the viewport height.
```
.example {
width: 50vw;
height: 30vh;
}
```


### %
- Relative to the parent element’s size.
- Often used for fluid layouts, where elements scale based on their parent’s size.
```
.parent {
  width: 400px;
}
.child {
  width: 25%; / *25% of the parent’s width (100px)* /
}
```

### Notes
- **em/rem**: Commonly used for scalable typography and spacing, ensuring accessibility and responsiveness.
- **%**: Common for layout, particularly with fluid widths and heights.
- **vw/vh**: Ideal for making elements responsive to the viewport size.
- **px**: A more fixed unit, suitable for exact pixel precision, but less flexible for responsiveness.
- **cm/in/pt/pc**: Rarely used in web design but may be useful in print-related CSS styles.


## Display Properties
### block
- Creates line breaks before and after itself.
- Occupies the full width of its container (unless a specific width is set).
- Conforms to the CSS box model, meaning it can have width, height, padding, margins, and borders.
```
div {
  display: block;
}
```
- If we want to display all the `block` level children side by side, then we have two options -
  - if use `float` property, then height of each child will not be the same, height of each child will depend on the content.
  - If we want to have same height for all the children irrespective of its content, then we will use `display:table` for the parent and `display:table-cell` for all the children. This technique is helpful, if we want to align the content to the center of parent container.


### inline
- Does not create a line break and flows with surrounding content.
- Only takes up as much space as needed, meaning it doesn't occupy the entire width of its parent.
- Does not follow the box model for width and height, but you can apply horizontal padding and margins. If vertical padding (top / bottom) is applied, but it does not affect line height or push surrounding elements vertically. The padding is visually present, but it does not change the layout flow.
```
span {
  display: inline;
}
```


### inline-block
- Combines the characteristics of both block and inline elements.
- Behaves like a block element, so you can apply width, height, padding, margins, and borders.
- Does not create a line break and can flow horizontally with other inline elements or text content.
```
button {
  display: inline-block;
  width: 150px;
  height: 50px;
}
```


### none
- Completely removes the element from the page flow (it will not take up space, and no other elements will flow around it).
- Useful for dynamically hiding elements (often controlled with JavaScript).
- Element will still be visible in DevTools, so it should not be used to obscure confidential information.
```
.hidden {
  display: none;
}
```
- `display:none` removes the element completely from the document flow and layout, but `visibility:hidden` hides the element visually but it still occupies its original space on the page. Opposite of `visibility:hidden` is `visibility:visible`.
