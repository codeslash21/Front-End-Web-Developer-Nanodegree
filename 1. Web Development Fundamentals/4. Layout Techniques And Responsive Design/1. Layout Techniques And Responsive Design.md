## Positioning
### Static
- This is the default position for most elements.
- Elements are positioned according to the normal document flow, meaning they appear where they would in the HTML without any adjustments.
```
.element {
  position: static;
}
```


### Relative
- The element is positioned relative to its normal position in the document flow.
- You can adjust its position using top, right, bottom, or left properties. These values shift the element from where it would normally be.
```
.element {
  position: relative;
  top: 10px;
  left: 20px;
}
```


### Absolute
- The element is positioned relative to its nearest positioned ancestor (i.e., an ancestor element with a position other than static), or to the initial containing block if no such ancestor exists.
- It removes the element from the document flow, meaning it doesn’t take up space and other elements will behave as if it doesn’t exist.
```
.parent {
  position: relative;
}

.child {
  position: absolute;
  top: 10px;
  left: 20px;
}
```


### Fixed
- The element is positioned relative to the viewport (the visible area of the browser window).
- It stays in place even when the user scrolls the page, which is useful for things like sticky headers or navigation bars.
```
.element {
  position: fixed;
  top: 10px;
  left: 20px;
}
```


### Sticky
- The element is initially positioned according to the normal document flow (like relative), but when you scroll past a certain point, it becomes fixed in place (like fixed).
- This is often used for sticky headers or sidebars.
```
.element {
  position: sticky;
  top: 0;
}
```


## Float
The float property in CSS is used to position an element to the left or right of its container, allowing other content to wrap around it. It removes the element from the normal document flow, which can be helpful for creating multi-column layouts and complex designs. Floats can be used to position elements side by side, such as in a two-column layout, by floating the left and right columns. Non-floating elements that come after a floated element will flow around it.
- **float: left**: Floats the element to the left, allowing content to wrap around the right side.
- **float: right**: Floats the element to the right, allowing content to wrap around the left side.

Floated elements are removed from the normal document flow, unlike inline elements, which still respect the flow and dimensions of surrounding elements. In the browser’s Developer Tools, you can see how floated elements sit outside of the normal flow. `float` property for an element, will only work if it has defined width and height.


### Clear Property
Floating elements can lead to layout issues. When floating elements are used inside a parent container, the parent’s height doesn’t automatically adjust to accommodate the floated children. A parent div with two floated child divs will have zero height, as the float property removes them from the document flow, causing layout issues. To fix the issue of a parent element collapsing when using floated children, we use the clear property. Applying `clear: both;` clears both left and right floated elements, ensuring that the element is placed below any floated elements and it will ensure the parent container wraps around its floated children correctly.

#### The clearfix technique
A common method to fix floated elements within their parent is to apply the clearfix hack, which can be done by adding an element with the clearfix class, ensuring the parent container properly wraps around its floated children.
```
.clearfix:after {
  content: "";
  display: table;
  clear: both;
}
```



## Flexbox
The Flexbox (Flexible Box) layout system is a CSS module designed to lay out items in a container in a flexible way. It provides a more efficient method for aligning and distributing space among items, even when their sizes are unknown or dynamic. Flexbox allows you to create complex layouts with ease, making it an essential tool for responsive web design.

- **Flex Container**: The parent element that holds the flex items and controls their behavior.
- **Flex Items**: The child elements inside the flex container that are arranged according to the flex properties.
- **Main Axis**: The primary axis along which flex items are aligned (default: left to right).
- **Cross Axis**: The axis perpendicular to the main axis (default: top to bottom).

### Display Mode
- **flex**: The flex container behaves as a block-level element, meaning it takes up the full width of its parent (most commonly used).
- **inline-flex**: The flex container behaves like an inline element, fitting into the flow of other inline content.


### Flexbox Properties

### Flex Container Properties
- **justify-content**: Aligns flex items along the main axis.
- **gap**: Specifies the space between flex items.
- **align-items**: Aligns flex items along the cross axis.
- **overflow: scroll**: Adds scrollbars to the container, allowing the user to scroll through the content. The overflow property is not exclusive to Flexbox and can be used with any container that has overflowed content.
- **flex-wrap**: Allows flex items to wrap onto multiple lines when necessary.
- **flex-direction**: Specifies the direction of the flex container's items.
- **flex-flow**: Combines flex-direction and flex-wrap into a single declaration.


### Flex Item Properties
- **flex-grow**: Defines how much a flex item will grow relative to the other items in the container when there is extra space available.. The default value is 0, meaning the item will not grow.
- **flex-shrink**: Defines how much a flex item will shrink relative to the other items in the container when there is not enough space.. The default value is 1, which allows items to shrink to fit in the container.
- **flex-basis**: Defines the initial size of a flex item before any space distribution occurs. This size can be specified as a length (e.g., px, em, %) or auto (which means the item's natural size).
- **flex**: Shorthand for flex-grow, flex-shrink, and flex-basis.



## CSS Grid
The CSS Grid layout allows us to control the positioning of child elements along both axes. The element with display: grid is called the grid container, and its child elements are known as grid items. By default, when `display: grid` is applied, the items are arranged in a single column, with each grid item placed in its own cell. This layout differs from the default block layout, where elements stack vertically.

### Grid Container Properties
#### Grid Template Column
- `grid-template-columns` defines the number and size of columns. Values can be space-separated, such as `auto`, to automatically size the columns. For example, four `auto` values create four automatically sized columns.
- If the columns are uniform in size, we can use the **repeat()** function, which simplifies the declaration by specifying the number of columns and their size. This reduces redundancy when all columns are the same size.
- The **fr** (fractional unit) is useful for defining columns that take up a proportion of available space. For example, `1fr` makes a column take up 1 fraction of the available space.
```
.grid-container {
  display: grid;
  grid-template-columns: 1fr 2fr 1fr;
}
```

#### Grid Template Areas
Instead of using numerical values, **grid-template-areas** allows you to assign variable names to different sections of the grid. This method makes it easier to visualize your layout. In the following example, the layout is defined with named areas: header, main, sidebar, and footer. The grid items will automatically fill these named areas based on their grid-area property.
```
.grid-container {
  display: grid;
  grid-template-areas:
    "header header header"
    "main main sidebar"
    "footer footer footer";
}

.header {
  grid-area: header;
}
.main {
  grid-area: main;
}
```

#### Grid Flow
By default, the grid fills out from left to right, row by row. However, we can modify this flow using the **grid-auto-flow** property. Declaring grid-auto-flow: column will make the grid flow from top to bottom, filling the first column first, then moving onto the next column.
```
.grid-container {
  display: grid;
  grid-auto-flow: column;
}
```

#### Aligning Items
- **justify-items** aligns grid items horizontally within their cells.
- **align-items** aligns grid items vertically within their cells.


### Grid Item Properties
- **justify-self** allows for horizontal alignment on individual grid items.
- **align-self** allows for vertical alignment on individual grid items.
- **grid-column-start** defines where a grid item starts along the horizontal axis.
- **grid-row-start** defines where a grid item starts along the vertical axis.
- **grid-column-end** defines where a grid item ends along the horizontal axis.
- **grid-row-end** defines where a grid item ends along the vertical axis.
- **grid-column**: A shorthand for grid-column-start and grid-column-end.
- **grid-row**: A shorthand for grid-row-start and grid-row-end.
- **grid-item** is shorthand for grid-row-start, grid-column-start, grid-row-end, grid-column-end.

CSS Media Queries allow you to apply different styles based on the characteristics of the device or viewport, such as its size, orientation, and resolution. This helps you make a responsive design that adjusts to different screen sizes and orientations, ensuring a better user experience across devices like smartphones, tablets, and desktops. A media query begins with the **@media** rule, followed by the condition you want to check, such as max-width or min-width. Inside the curly braces, you place the CSS rules that will be applied if the condition is met. You can specify various conditions in your media queries, called **media features**. These features allow you to target specific properties of the viewport or device. The order in which media queries are declared in the CSS file matters. CSS follows a **cascading order**, meaning that the styles from the last declared rule take precedence.
```
@media (max-width: 768px) and (orientation: landscape) {
  .container {
    width: 80%;
  }
}

@media (min-width: 640px), (orientation: landscape) {  // for OR either condition must be true
  .content {
    margin: 20px;
  }
}

@media not (min-width: 1000px) {  // rule applies for all viewports except those that are at least 1000px wide
  .header {
    background-color: red;
  }
}

@media (aspect-ratio: 16/9) {  // aspect ratio is width-to-height ratio
  .video-container {
    padding: 56.25% 0 0 0;
  }
}

// Targets devices with a specific pixel density, useful for delivering high-DPI images (e.g., Retina displays).
// dpi -> Dots Per Inch, but technically it's more accurately called PPI (Pixels Per Inch), measuring how many
// pixels fit into one inch of the display, with a higher number meaning sharper images and text.
@media (min-resolution: 192dpi) {
  .logo {
    background-image: url('logo-high-res.png');
  }
}

@media (hover: hover) {  // Detects if a device supports hover (like a mouse)
  .button {
    cursor: pointer;
  }
}

// Detects if a device supports precision of the pointing device (e.g., fine-tuned pointer vs touchscreen)
@media (pointer: fine) {  
  .button {
    padding: 15px;
  }
}

// to provide alternative styles for users who prefer reduced motion for accessibility reasons.
@media (prefers-reduced-motion: reduce) {
  .animated-element {
    animation: none;
    transition: none;
  }
}
```
## Mobile First Design
### Benefits
- **Improved User Experience**: Prioritizes essential content, offering a simpler, more accessible layout that’s easier to navigate on smaller devices.
- **Faster Deployment**: By focusing on a minimal version first, you can quickly reach your Minimum Viable Product (MVP) and deploy faster.
- **More Efficient**: A mobile-first approach encourages lean, efficient code that not only improves performance on mobile but also benefits more powerful devices.
- **Better SEO**: Mobile-first designs are favored by search engines like Google, which use the mobile version of a site for indexing and ranking.
- **Universal Presentability**: Designing for smaller screens first ensures that scaling up to larger screens is simpler and more adaptable than starting with larger devices.


### Principles
- **Prioritize Core Content**: Focus on the essential content that needs to be displayed on a mobile screen. Eliminate non-essential features and design elements to avoid clutter and enhance accessibility, making it easier for users to access the most important information.
- **Progressive Enhancement**: Start with a simple, mobile-friendly design. Once the mobile version is stable, add additional features and layout adjustments for larger screens. This allows the website to grow from a solid foundation.
- **Performance Optimization**: Optimize for slower networks and less powerful devices. Compress images, reduce JavaScript, and minimize API calls to improve loading times. This not only benefits mobile users but also reduces bandwidth usage and costs.
- **Responsive Design with Media Queries**: Use CSS Media Queries to implement breakpoints based on viewport size. Mobile is the default, and larger screens should add extra features and layouts, rather than the other way around.
- **Touch-Friendly Design**: Ensure interactive elements are large enough and spaced out for easy tapping on touchscreens. Avoid relying on hover interactions, as they won’t work on mobile devices, and instead focus on making interactions clear through design and semantics.
- **Readability**: Ensure that text is large enough to be easily read on small screens without zooming. Break up large blocks of text into smaller paragraphs and increase white space to improve readability. Don’t forget to include the viewport meta tag to ensure proper scaling.
